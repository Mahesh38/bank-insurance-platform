## 2. Purpose

This BRD defines the login, multi-factor authentication, account-lock, account-unlock, first-time activation and partner password-management requirements for the new Digital Insurance Platform. It separates the Bank RM and Insurance Partner RM journeys because the two users have different login identifiers, password ownership and account-recovery behaviour.

## 3. Business Objective

The objective is to provide secure and simple access to the platform while using the bank authentication system for Bank RMs and platform-managed authentication for Insurance Partner RMs. Every successful login will require OTP verification sent to the registered mobile number and email ID.

## 4. Scope

The module covers user-type selection, login validation, Captcha, mandatory OTP on every login, account locking after failed password attempts or inactivity, Unlock User, first-time partner password creation, forgotten/expired partner password reset through Unlock User, successful login redirection, error handling and audit logging.

### 4.1 In Scope

- Bank RM login through Employee ID and bank system password
- Insurance Partner RM login through Corporate Email ID and platform password
- Captcha validation
- OTP verification on every login
- Account lock after three consecutive incorrect password attempts
- Account lock after 30 days of inactivity
- Unlock User for both user types
- First-time Insurance Partner RM password creation through Unlock User
- Insurance Partner RM forgotten-password reset through Unlock User
- Insurance Partner RM password expiry after 60 days
- Audit logs and user-facing error handling
- Get Help / support contact display
- Downloadable Unlock User guide, subject to IT-provided content
### 4.2 Out of Scope

- Bank RM password creation, reset or change within this platform
- Separate Forgot Password functionality for either user type
- User onboarding and user-master creation
- Maintenance of registered mobile number and email ID
- Bank enterprise authentication policy definition
- Administration of Captcha, SMS gateway or email gateway
- Dashboard functionality after successful login

## 6. End-to-End Login Flows

### 6.1 Bank RM Login

- User opens the login page and selects Bank RM.
- User enters Employee ID, bank system password and Captcha.
- System validates mandatory fields and Captcha.
- Credentials are validated through the bank authentication service.
- On successful credential validation, the platform generates a six-digit OTP.
- The same OTP is sent to the registered mobile number and registered email ID.
- User enters and verifies the OTP.
- On successful OTP verification, the user is redirected to the Bank RM dashboard.
### 6.2 Insurance Partner RM Login

- User opens the login page and selects Insurance Partner.
- User enters Corporate Email ID, platform password and Captcha.
- System validates mandatory fields, email format and Captcha.
- Credentials are validated by the platform authentication service.
- On successful credential validation, the platform generates a six-digit OTP.
- The same OTP is sent to the registered mobile number and registered email ID.
- User enters and verifies the OTP.
- On successful OTP verification, the user is redirected to the Insurance Partner RM dashboard.

## 9. Security and Session Requirements

SEC-001: All login and Unlock User pages shall be served only over secure encrypted transport.

SEC-002: Passwords and OTPs shall not be written to application, API, audit or monitoring logs.

SEC-003: Sensitive user details displayed on the OTP screen shall be masked.

SEC-004: The platform shall prevent duplicate form submissions while authentication is in progress.

SEC-005: An OTP shall be mapped to the user and verification session and shall not be valid for another user or session.

SEC-006: After successful login, the system shall create an authenticated session and route the user to the dashboard applicable to the selected user type.

SEC-007: On failed authentication, the response shall not disclose unnecessary account information beyond the agreed user-facing messages.

SEC-008: Browser back navigation after logout or session expiry shall not expose authenticated pages.

SEC-009: Session timeout and concurrent-session rules shall follow the approved bank Information Security standard.

SEC-010: Captcha generation, complexity and expiry shall follow the approved Captcha service and Information Security standard.

## 16. Key Business Rules Summary

KBR-01: Bank RM logs in with Employee ID and bank system password.

KBR-02: Insurance Partner RM logs in with Corporate Email ID and platform password.

KBR-03: OTP is mandatory on every login and is sent to both registered mobile number and email ID.

KBR-04: Accounts lock after three consecutive incorrect password attempts.

KBR-05: Accounts also require unlocking after 30 days without login.

KBR-06: Unlock User is available for both users and is the only account-recovery function on the login page.

KBR-07: Bank RM password cannot be created, reset or changed in this platform.

KBR-08: A first-time Insurance Partner RM creates a password through Unlock User.

KBR-09: Insurance Partner RM forgotten or expired password is reset through Unlock User.

KBR-10: OTP validity is 10 minutes, with five incorrect attempts, resend after two minutes and a maximum of three resends.

KBR-11: Insurance Partner RM password length is 8-20 characters with uppercase, lowercase, number and special character.

KBR-12: Insurance Partner RM password expires after 60 days.

KBR-13: Separate Forgot Password shall not be displayed.

KBR-14: All authentication and recovery events must be audited without storing passwords or OTP values.
