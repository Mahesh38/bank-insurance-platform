## 2. Purpose

This BRD defines the seller-assisted Quote Finalisation journey initiated after Buy Now. The seller confirms the final base-plan configuration, optionally selects and configures riders, reviews the final quote and customer details, generates the final customer-specific Benefit Illustration, optionally shares it, completes Insurance RM assignment where applicable, and proceeds to the Proposal Form. Application ID is generated only when the Proposal Form is successfully initiated.

## 3. Business Objectives

- Allow the seller to finalise one selected Savings product using insurer-supported quote inputs.
- Allow optional riders to be added and configured through API-driven forms.
- Automatically include inbuilt riders or benefits without permitting seller changes.
- Provide one consolidated Quote Summary before final BI generation.
- Generate an immutable customer-specific final BI containing the exact final product and rider configuration.
- Apply Lead eligibility, stage, Suitability lock and reassignment controls only after successful BI generation.
- Support role-specific post-BI Insurance RM assignment and controlled Proposal Form initiation.

## 6. End-to-End Journey

STEP-01: Seller selects Buy Now.

STEP-02: Detailed Quote opens with the exact selected product and latest quote inputs.

STEP-03: Seller confirms or changes the base-plan configuration.

STEP-04: Platform refreshes the detailed quote and Returns Breakdown.

STEP-05: Seller selects Confirm and Proceed.

STEP-06: Rider Selection page opens.

STEP-07: Seller adds/configures optional riders, reviews inbuilt riders, or skips optional riders.

STEP-08: Platform recalculates premium after every valid rider change.

STEP-09: Quote Summary displays the final base plan, riders, customer details and premium breakup.

STEP-10: Seller selects Generate Benefit Illustration.

STEP-11: Platform validates the complete final quote and calls the BI API.

STEP-12: On success, the Lead becomes Eligible and stage becomes Quote Generated; Suitability and reassignment are locked.

STEP-13: Seller may optionally view, download or share the BI.

STEP-14: Bank RM completes Insurance Partner and Insurance RM assignment where applicable. Insurance RM journey skips this assignment.

STEP-15: Seller selects Continue to Proposal Form.

STEP-16: Application ID is generated and the Lead Stage changes to Proposal Form Pending.

## 8. Returns Breakdown

- The complete breakdown shall be received from the applicable Quote API as an ordered label/value set.
- Possible values include investment, total invested, PPT, Policy Term, maturity value, guaranteed income, illustrated income, IRR, Annualised Return, Life Cover and multiplier.
- The platform shall not independently calculate return values.
- Guaranteed and non-guaranteed values shall be clearly distinguished.
- For Participating plans, use the latest selected 4% or 8% scenario; 8% remains the default unless carried otherwise from Product Details.
- For Non-Participating plans, do not show the 4%/8% selector.
- Hide non-applicable components and use Not Available only for applicable but missing values.
- The breakdown must match the current Quote Reference.

## 12. Rider Actions and Recalculation

### 12.1 Add Rider

- Validate all API-defined mandatory fields.
- Call rider quote API.
- Add the rider only after successful premium calculation.
- Update Rider Premium, Total Rider Premium, taxes, charges, Total Premium Payable and Premium Breakup.
- Create a new Quote Version.
- Do not generate the BI.
### 12.2 Edit Rider

- Open the current saved configuration prefilled.
- Allow only API-permitted fields to change.
- Apply revised values only after successful recalculation.
- Retain the previous valid configuration if recalculation fails.
### 12.3 Remove Rider

- Allow removal only for optional riders.
- Refresh quote, taxes and totals after removal.
- Remove the rider from Quote Summary and final BI request.
- Do not permit removal of inbuilt riders.
### 12.4 Skip Riders

- If no optional rider is added, proceed directly to Quote Summary.
- Inbuilt riders remain included.
- If optional riders were already added, request confirmation to remove all optional riders and continue.
- Refresh total premium after confirmed removal.
## 13. Base-Plan Change Impact on Riders

- Changing plan option, amount, frequency, PPT, Policy Term or return preference shall trigger rider revalidation.
- Retain riders that remain eligible and refresh their premiums where required.
- Clear or remove riders that are no longer valid and inform the seller.
- Require reconfiguration where a rider remains available but its prior values are invalid.
- Block Quote Summary and BI generation until all rider states are valid.
- Inbuilt rider data identified by API is mandatory for final configuration; missing mandatory inbuilt data blocks BI generation.

## 16. BI Success and Failure

### 16.1 Successful BI

- Set BI Generated = Yes.
- Change Lead Stage to Quote Generated.
- Classify the Lead as Eligible for applicable reporting.
- Lock Suitability and make it read-only.
- Block lead reassignment.
- Store immutable BI Reference and BI Version.
- Preserve exact product, rider, premium and illustration configuration.
- Open Quote Created confirmation.
### 16.2 Failed BI

- BI Generated remains No.
- Lead Stage does not change to Quote Generated.
- Lead does not become Eligible.
- Suitability remains editable.
- Reassignment remains allowed if otherwise eligible.
- Latest valid quote and rider configuration remain saved.
- Seller may retry without rebuilding the full quote.
## 17. Multiple BI Versions

- One Lead may have multiple customer-specific BIs.
- Every BI has a separate reference and immutable version.
- Earlier BIs shall not be overwritten.
- A revised base plan or rider configuration requires a fresh quote and new BI version.
- The latest successful BI may be marked current.
- Sharing shall identify the exact BI version being sent.

- After Application ID success, resume opens the existing Proposal Form.

## 29. Key Business Rules Summary

KBR-01: Buy Now opens Detailed Quote for the exact selected Savings product.

KBR-02: Base-plan quote inputs remain editable and API validated.

KBR-03: Only Annual and Single Premium frequencies are supported.

KBR-04: All optional riders may be skipped.

KBR-05: Inbuilt riders are API defined, fixed and uneditable.

KBR-06: Rider configuration is fully API driven.

KBR-07: Rider add, edit, remove or base-plan change refreshes the quote.

KBR-08: Quote Summary customer details are read-only.

KBR-09: Premium Breakup comes from API and must match Total Premium.

KBR-10: The final action is Generate Benefit Illustration.

KBR-11: A BI exists only after a successful valid BI API response.

KBR-12: Successful BI makes the Lead Eligible, changes stage to Quote Generated, locks Suitability and blocks reassignment.

KBR-13: BI sharing is optional through Email, SMS and WhatsApp.

KBR-14: Sharing failure does not affect BI success or onward progression.

KBR-15: Bank RM selects Insurance Partner and Insurance RM after BI, before Proposal Form.

KBR-16: Insurance RM does not see the post-BI assignment because SP was selected earlier.

KBR-17: Application ID is generated only when Proposal Form starts.

KBR-18: BI generation does not create Application ID.

KBR-19: The same Lead ID continues throughout.

KBR-20: All key events and versions are audited.
